The real question Composite solves is:
How do I represent AND work with a recursive tree structure?

Order
 ├── Item A
 ├── Item B
 └── Bundle
       ├── Item C
       └── Item D

if (item is SimpleItem) {
    return price;
}
if (item is Bundle) {
    for each child → calculate
}

🔴 Problem:
* You must know types
* Logic spreads everywhere
* Recursion becomes messy

Composite says:
Make EVERY node responsible for its own behavior

💡Key Idea:
"Let objects call themselves recursively"

Instead of YOU managing the tree, You let THE TREE manage itself

🎯 So WHY Composite Exists?

Not just for generalization.

👉 It exists to:

Handle tree structures WITHOUT type checking
