📌 Definition
Composite Pattern =
    "treat individual objects and compositions of objects uniformly"

🎯 So WHY Composite Exists?
The real question Composite solves is:
    "How do I represent AND work with a recursive tree structure?"

Not just for generalization.

👉 It exists to:
    "Handle tree structures WITHOUT type checking"

Order
 ├── Item A
 ├── Item B
 └── Bundle
       ├── Item C
       └── Item D

Composite says:
    "Make EVERY node responsible for its own behavior"

if (item is SimpleItem) {
    return price;
}
if (item is Bundle) {
    for each child → calculate
}

🔥 Where You’ll Use It in Backend (REAL USE CASES)
*  Pricing / Billing Systems (VERY COMMON)
   * products
   * bundles
   * discounts
   * Item

*  Permission Systems
    Role
     ├── Permission
     └── Role (nested roles)
👉 recursive roles

*  Menu / Category Trees
    Category
     ├── Subcategory
     │     └── Product

*  Comment Systems (like Reddit)
    Comment
     ├── Reply
     │     └── Reply

*  Organization Structures
    Manager
     ├── Employee
     └── Manager

💡Key Idea:
    "Let objects call themselves recursively"
Instead of YOU managing the tree, You let THE TREE manage itself

❌ When NOT to Use It
If:
   * No recursive structure
   * No tree
Then don’t use it.
